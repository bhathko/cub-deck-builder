# 簡報產生器 — 給設計師的白話說明

> 這份文件不講程式,講「它為什麼這樣設計、每個檔案是幹嘛的、以後怎麼讓它變更好」。
> 想看工程細節的人請讀 `README.md` 與 `WORKLOG.md`。

## 一句話介紹

把一段文字大綱貼給我們的 ChatGPT GPT,它會用**公司模板**產出一份**可編輯的
PowerPoint**——而且每一步都被「真的會執行的檢查程式」把關,不是 AI 憑感覺畫的。

## 為什麼要這樣設計?

直接叫 ChatGPT「幫我做簡報」有三個老問題:

1. **每次長得不一樣**——同樣內容今天做一版明天做一版,版面漂移。
2. **會編數字**——你沒給的 KPI 它敢自己補,拿去報告會出事。
3. **版面不像公司模板**——它畫的是「它心中的簡報」,不是我們的規範。

所以這套系統的核心理念是:**AI 只准做它擅長的,其他交給固定程式**。
用餐廳來比喻:

| 角色 | 是誰 | 做什麼 |
| --- | --- | --- |
| 客人 | 你 | 給一段大綱(想講什麼) |
| 服務生 | AI | 把你的話填進「點菜單」(選頁型、填欄位),**不准下廚** |
| 廚房 | 固定程式(腳本) | 照 SOP 出菜:複製模板頁、填字、排頁碼,零即興 |
| 品管 | 檢查程式 ×2 | 出菜前驗規格、出菜後再自檢,沒過就退回重做 |

三條鐵律:

- **版面 AI 零參與**:所有版面來自 `light_template.pptx`(公司模板),由程式
  複製與填字。同一份內容跑一百次,產出一模一樣。
- **內容不准編**:你給的文字是唯一來源。程式會逐字比對——標題必須是你原文的
  句子、任何數字必須在你原文出現過(原文寫 50,產出不能變 5)。你沒給的資料
  一律寫「**待補充**」,絕不瞎編。
- **兩道檢查門**:產檔前驗規格(欄位、字數、頁碼、素材),產檔後再自檢一次;
  任何一關沒過,寧可不交件。

## 怎麼用(請直接試)

1. 打開 GPT,**直接貼你的大綱**,不用打任何指令。
2. 缺的資料(日期、報告人、數據)標「待補充」就好,它會先做出結構,之後你補
   資料再貼一次就補齊。
3. 想要圖表(甘特圖、滿意度圖…)請附數據;沒數據它會用文字頁保留位子,
   欄位填「待補充」——它不會幫你畫假圖表。
4. 交付時會拿到:**PPTX + 一份 JSON(這次簡報的規格書)+ 待補清單**。
5. 產出請用 PowerPoint 開起來看(AI 的沙箱沒有中文字體,無法給可靠預覽圖)。
6. 全部都是可編輯物件,想微調直接在 PowerPoint 改。

## 每個檔案在做什麼(白話版)

### 裝進 GPT 的 11 個檔案(它的「隨身裝備」)

| 檔案 | 白話角色 |
| --- | --- |
| `instructions.md` | GPT 的**工作守則**,貼在 GPT 設定裡:什麼該做、什麼絕不准做 |
| `light_template.pptx` | **公司模板本體**——所有版面的唯一來源 |
| `page_types_registry.md` | **小菜單**:10 種全自動頁型的填寫規則(有哪些欄位、字數上限) |
| `page_types.md` | **大菜單**:50 種頁型的型錄,每種長怎樣、適合放什麼內容 |
| `style_guide.md` | 視覺規範(顏色、字級、logo 與頁碼位置) |
| `validate_slide_spec_gpts.py` | **檢查員 1 號**:產檔前驗規格,不合格就擋下 |
| `slide_spec.schema.json` | 規格書(點菜單)的格式定義 |
| `slide_spec.example.json` | 一份「合格點菜單」範例 |
| `slide_spec.bad.example.json` | 一份「故意不合格」的範例(測試檢查員有沒有在做事) |
| `assets.zip` | 背景圖 ×3 + 公司 logo |
| `tools.zip` | **整間廚房**:9 支程式(見下表) |

### tools.zip 裡的 9 支程式(廚房分工)

| 程式 | 白話角色 |
| --- | --- |
| `run_pipeline.py` | **總指揮**:一條指令跑完「稽核→驗規格→產檔→品管」,任一關失敗就停 |
| `audit_provenance.py` | **檢查員 0 號**:比對內容忠實度——標題逐字、數字精確(50 不能變 5) |
| `make_skeleton.py` | 印**空白點菜單**(保證格式正確的規格書骨架) |
| `render_deck.py` | **主廚**:照模板把規格書變成 PPTX,每次從模板整份重做 |
| `fills.py` | 10 種全自動頁型的**自動填字員**(哪個字進哪個框,寫死的) |
| `pptx_toolkit.py` | 廚房基本功:複製模板頁(圖不會破)、刪頁、排序 |
| `text_tools.py` | 換字不換樣式、偵測文字會不會爆框 |
| `inspect_template.py` | **模板放大鏡**:盤點模板某一頁裡有哪些框 |
| `qa_check.py` | **檢查員 2 號**:產檔後自檢(頁數、字體、頁碼、溢出) |

## 頁型的兩個等級

- **10 種「全自動」頁型**:封面、目錄、封底、章節頁、願景目標、三欄說明、
  前後數據比較、方案評估、金字塔、雙軌時程。這些從填字到排版**全程式處理**,
  AI 零參與版面,品質最穩。
- **其他 40 種「半自動」頁型**:也能用,但 AI 要多寫一張小抄(告訴程式
  「模板第幾頁的哪個框換成什麼字」),穩定度略低、檢查也較寬鬆。

**所以頁型升級是這個系統變強的主要路徑**:把常用的半自動頁型升級成全自動。

## 以後怎麼新增「全自動」頁型

設計師是提需求的人,你們的輸入最關鍵。流程白話版:

1. **發現需求**(設計師):某種頁型常常用到、或半自動版本產出不穩,
   到 `FEEDBACK.md` 登記,或直接跟管理者說「這種頁我們每週都在做」。
   同一頁型被登記兩次以上,就是升級的訊號。
2. **工程升級**(管理者,一種頁型約半天):
   - 在檢查員 1 號裡定義這種頁的「契約」(有哪些欄位、幾個項目、字數上限)
   - 同步更新小菜單(`page_types_registry.md`)與規格書格式
   - 在自動填字員(`fills.py`)裡寫死「哪個欄位進模板哪個框」
   - 重新打包、上傳、跑驗收
3. **驗收**(設計師+管理者):拿真實內容產幾份,跟模板頁並排比對。

### 設計師的回饋怎麼給才有效

GPT **沒有記憶**,在對話裡罵它糾正它,關掉對話就忘了。要讓它「以後都對」,
回饋必須變成寫進檔案的規則。最有效的回饋長這樣:

- **能用一句話說出「以後應該怎樣」**,那句話就是規則。
  例:「三欄卡片的欄距要跟模板第 17 頁一樣寬」——這句可以直接寫進規則檔。
- 說不出來、只覺得醜:附**模板參考頁**和**產出**的並排截圖,讓管理者判斷差在哪。
- 當場在對話裡下的修正指令(「第 3 頁參考模板第 17 頁重排」)特別值錢,
  修好之後把那句話交給管理者。

## 常見問題

**Q:為什麼有些欄位是「待補充」?**
因為你沒給那個資料。這是刻意設計:它寧可留空位讓你補,也不編一個假數字。
把真實資料貼回去重跑一次就補齊了。

**Q:可以叫它畫插圖或生成圖片嗎?**
不行。公司政策不允許,而且產出必須全部是可編輯物件(方便你們後續調整)。

**Q:為什麼它給的預覽圖中文是方塊?**
AI 沙箱沒有中文字體。檔案本身沒問題,用 PowerPoint 開就正常。

**Q:它會不會有時候「鬧脾氣」說做不到?**
GPT 設定裡務必指定最強模型(目前是 GPT-5.6 Pro)。我們實測過:弱模型會
拒絕執行工具、亂給替代方案;強模型全流程順跑。如果遇到,先問它
「你現在是哪一版?」再回報給管理者。

**Q:產出哪裡不滿意,可以自己改嗎?**
可以,PPTX 全部可編輯。但如果同樣的問題出現第二次,請走回饋流程讓它
變成規則——當場修只救這一次,規則化才救以後每一次。
