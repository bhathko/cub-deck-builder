# 簡報產生器 — 給設計師的白話說明

> **用途**:不講程式,講「它為什麼這樣設計、每個檔案是幹嘛的、以後怎麼讓它變更好」。
> **讀者**:設計師與非技術同事(這份可以直接轉發)。
> **何時讀**:第一次接觸這套工具時;想提需求或回報問題前;
> **想自己動手新增一套模板時看文末附錄(逐步指令版)**。
> 想看工程細節請讀 repo 根的 `README.md` 與 `docs/WORKLOG.md`。

## 一句話介紹

把一段文字大綱貼給我們的 ChatGPT GPT,它會用**公司模板**產出一份**可編輯的
PowerPoint**——而且每一步都被「真的會執行的檢查程式」把關,不是 AI 憑感覺畫的。

## 為什麼要這樣設計?

直接叫 ChatGPT「幫我做簡報」有三個老問題:

1. **每次長得不一樣**——同樣內容今天做一版明天做一版,版面漂移。
2. **會編數字**——你沒給的 KPI 它敢自己補,拿去報告會出事。
3. **版面不像公司模板**——它畫的是「它心中的簡報」,不是我們的規範。

所以這套系統的核心理念是:**AI 只准做它擅長的,其他交給固定程式**。
用餐廳來比喻:

| 角色 | 是誰 | 做什麼 |
| --- | --- | --- |
| 客人 | 你 | 給一段大綱(想講什麼) |
| 服務生 | AI | 把你的話填進「點菜單」(選頁型、填欄位),**不准下廚** |
| 廚房 | 固定程式(腳本) | 照 SOP 出菜:複製模板頁、填字、排頁碼,零即興 |
| 品管 | 檢查程式 ×2 | 出菜前驗規格、出菜後再自檢,沒過就退回重做 |

三條鐵律:

- **版面 AI 零參與**:所有版面來自公司模板(目前是 light 模板包),由程式
  複製與填字。同一份內容跑一百次,產出一模一樣。
- **內容不准編**:你給的文字是唯一來源。程式會逐字比對——標題必須是你原文的
  句子、任何數字必須在你原文出現過(原文寫 50,產出不能變 5)。你沒給的資料
  一律寫「**待補充**」,絕不瞎編。
- **兩道檢查門**:產檔前驗規格(欄位、字數、頁碼、素材),產檔後再自檢一次;
  任何一關沒過,寧可不交件。

## 怎麼用(請直接試)

1. 打開 GPT,**直接貼你的大綱**,不用打任何指令。
2. 缺的資料(日期、報告人、數據)標「待補充」就好,它會先做出結構,之後你補
   資料再貼一次就補齊。
3. 想要圖表(甘特圖、滿意度圖…)請附數據;沒數據它會用文字頁保留位子,
   欄位填「待補充」——它不會幫你畫假圖表。
4. 交付時會拿到:**PPTX + 一份 JSON(這次簡報的規格書)+ 待補清單**。
5. 產出請用 PowerPoint 開起來看(AI 的沙箱沒有中文字體,無法給可靠預覽圖)。
6. 全部都是可編輯物件,想微調直接在 PowerPoint 改。

## 頁型的兩個等級

- **11 種「全自動」頁型**:封面、目錄、封底、章節頁、願景目標、三欄說明、折線趨勢(含圖表數據)、
  前後數據比較、方案評估、金字塔、雙軌時程。這些從填字到排版**全程式處理**,
  AI 零參與版面,品質最穩。
- **其他 40 種「半自動」頁型**:也能用,但 AI 要多寫一張小抄(告訴程式
  「模板第幾頁的哪個框換成什麼字」),穩定度略低、檢查也較寬鬆。

**所以頁型升級是這個系統變強的主要路徑**:把常用的半自動頁型升級成全自動。

## 想換一整套版型?——新增「模板包」

2026-07 起支援多套模板:除了現在的 Cathay 淺色風,設計師可以再交新的
`.pptx` 進來,產檔時說「用○○模板」就換一整套版面。

**先決定你走哪條路:**

| | 路線 A:交給管理者 | 路線 B:我自己來 |
| --- | --- | --- |
| 你要做的 | 交檔、用嘴回答、開檔目檢 | 同左,再加上自己打指令 |
| 要開終端機嗎 | **不用** | 要 |
| 大概花多久 | 你這邊 15 分鐘 | 40–60 分鐘(第一次更久) |
| 適合誰 | 所有人。**不確定就選這條** | 想少一次來回、願意複製貼上的人 |

兩條路的產出**完全一樣**——同一套工具、同一份驗收檔。
路線 B 不會讓模板變好,只是不用等管理者。

### 路線 A:交給管理者(推薦)

你要做的只有三件事:

1. **交一份模板 .pptx 給管理者**,順便取個名字(例如「企業深色風」)。
   模板裡的每種版面就是之後可以用的頁型;含 SmartArt 的頁程式動不了,
   會被跳過(可以先在 PowerPoint 把它轉成一般圖形再交)。
2. **回答「這頁是什麼」**:管理者會跑一個註冊精靈,它逐頁問你
   「第 18 頁看起來像『願景目標』還是『核心與支援』?」——你用嘴回答就好,
   shape id、JSON 這些完全不會拿來煩你。
3. **打開驗收檔目檢點頭**:精靈會產一份驗收簡報,每種頁型兩頁——
   一頁塞最少內容(看有沒有殘留空框)、一頁塞最滿(看有沒有爆框)。
   **機器檢查全過也不代表視覺沒問題,所以一定要你看過才算完成。**

註冊完的模板會有一張「支援矩陣」:哪些頁型全自動、哪些半自動、哪些不支援
(附原因)。**部分支援是正常結局**——不必為了「全部支援」把模板改得四不像。

### 路線 B:我自己來(要開終端機,約 40 分鐘)

「自己來」不是要你寫程式,而是**照著抄五行指令**;中間最難的那段
(哪個框該放什麼字)還是 AI 精靈幫你寫。你負責的仍然是那三件事:
交檔、回答、目檢。

可以放心的地方:整個過程都在你自己的電腦上跑、**不上傳任何東西**;
做壞了管理者用 git 一句話就能還原;而且**每一步失敗都是當場停住**,
不會留下一個半殘的模板害到別人。

完整逐步指令在文件最後的〈附錄:自己動手註冊新模板〉。第一次做的時候
把附錄開著跟著走,遇到紅字先看附錄的〈看到紅字,先做這三件事〉。

### 三件事別搞混:我能自己做到哪裡?

| | 這是什麼 | 誰可以做 |
| --- | --- | --- |
| **A. 交一整套新模板** | 給一個新 `.pptx`,讓它變成可選的模板 | **設計師可以自己發起**(路線 A 或 B) |
| **B. 讓某個頁型在我的模板裡變全自動** | 那種頁型系統已經認得(目前 11 種),只是我的模板還沒綁 | **仍在精靈範圍內**,不必找工程師 |
| **C. 發明一種全新的頁型** | 系統從來沒有過的版面語意(例如「五欄比較表」) | **要找工程師**——這會改到所有模板共用的規則,有一套三處同步流程 |

白話版:**「我的模板要支援某種頁型」可以自己來;「這世界上要多一種頁型」不行。**
分不清的時候看這個:那種版面在現有 11 種全自動頁型裡找得到相似的嗎?
找得到就是 B(自己來),找不到就是 C(先跟管理者提需求)。

## 以後怎麼新增「全自動」頁型

設計師是提需求的人,你們的輸入最關鍵。流程白話版:

1. **發現需求**(設計師):某種頁型常常用到、或半自動版本產出不穩,
   到 `docs/FEEDBACK.md` 登記,或直接跟管理者說「這種頁我們每週都在做」。
   同一頁型被登記兩次以上,就是升級的訊號。
2. **工程升級**(管理者,一種頁型約半天):
   - 在檢查員 1 號裡定義這種頁的「契約」(有哪些欄位、幾個項目、字數上限)
   - 同步更新小菜單(`page_types_registry.md`)與規格書格式
   - 在該模板包的填字對照表(`bindings.json`)加一筆綁定,寫明「哪個欄位進模板哪個框」
   - 重新打包、上傳、跑驗收
3. **驗收**(設計師+管理者):機器先跑黃金驗收(最少/最滿內容各一份),
   全綠後**由設計師打開檔案目檢點頭**才算完成——機器綠不等於視覺不爆框。

### 設計師的回饋怎麼給才有效

GPT **沒有記憶**,在對話裡罵它糾正它,關掉對話就忘了。要讓它「以後都對」,
回饋必須變成寫進檔案的規則。最有效的回饋長這樣:

- **能用一句話說出「以後應該怎樣」**,那句話就是規則。
  例:「三欄卡片的欄距要跟模板第 17 頁一樣寬」——這句可以直接寫進規則檔。
- 說不出來、只覺得醜:附**模板參考頁**和**產出**的並排截圖,讓管理者判斷差在哪。
- 當場在對話裡下的修正指令(「第 3 頁參考模板第 17 頁重排」)特別值錢,
  修好之後把那句話交給管理者。

## 常見問題

**Q:為什麼有些欄位是「待補充」?**
因為你沒給那個資料。這是刻意設計:它寧可留空位讓你補,也不編一個假數字。
把真實資料貼回去重跑一次就補齊了。

**Q:可以叫它畫插圖或生成圖片嗎?**
不行。公司政策不允許,而且產出必須全部是可編輯物件(方便你們後續調整)。

**Q:為什麼它給的預覽圖中文是方塊?**
AI 沙箱沒有中文字體。檔案本身沒問題,用 PowerPoint 開就正常。

**Q:它會不會有時候「鬧脾氣」說做不到?**
GPT 設定裡務必指定最強模型(目前是 GPT-5.6 Pro)。我們實測過:弱模型會
拒絕執行工具、亂給替代方案;強模型全流程順跑。如果遇到,先問它
「你現在是哪一版?」再回報給管理者。

**Q:產出哪裡不滿意,可以自己改嗎?**
可以,PPTX 全部可編輯。但如果同樣的問題出現第二次,請走回饋流程讓它
變成規則——當場修只救這一次,規則化才救以後每一次。

# 附錄:自己動手註冊新模板(逐步指令版)

> 這是〈路線 B〉的完整操作手冊。下面每一條指令都在 2026-07-26 實際跑過,
> 連錯誤訊息都是真的。**建議開著這頁跟著做**,不要憑印象打。
> 全程在你自己的電腦上跑,不上傳任何東西。

## A0. 先打開「終端機」

終端機就是一個**用打字跟電腦講話的窗口**:沒有按鈕、沒有選單,你打一行字、
按 Enter,它回你幾行字。看起來很嚴肅,但**它只會做你叫它做的事**。

- **Mac**:按 `⌘ + 空白鍵`,打「Terminal」,按 Enter。
- **Windows**:按開始鍵,打「PowerShell」,按 Enter。

三個第一次一定會卡的小事:

- **貼上**:Mac 按 `⌘V`;Windows 在視窗裡按**滑鼠右鍵**就是貼上。
- **游標**:滑鼠點不動游標,只能用左右方向鍵移動。打錯就按退格鍵刪掉重打。
- **指令從哪來**:**整行從這份文件複製**,不要手打。特別不要經過 Word、
  LINE 或會「美化引號」的軟體——它們會把 `"` 換成彎引號 `"`,程式不認得。

## A1. 讓終端機「站」到專案資料夾裡

終端機每一刻都站在某個資料夾裡,就像 Finder 視窗現在開在某個資料夾。
所有指令都是**相對於它站的位置**,所以第一件事是叫它站進 `ppppai` 資料夾。

不用背路徑,用拖的:

1. 打 `cd`,然後打**一個空格**(這個空格不能少)。
2. 在 Finder / 檔案總管找到 `ppppai` 資料夾,**直接拖進終端機視窗**,
   路徑會自動貼上。
3. 按 Enter。

確認站對了(這行純粹是看,絕對安全):

```
ls
```

Windows 打 `dir`。看到 `engine`、`gpts`、`docs` 這幾個資料夾就對了。

> 找不到 `ppppai` 資料夾?表示你電腦上還沒有這個專案,跟管理者要——
> 這一步他要幫你做一次(之後就不用了)。

## A2. 我的模板 .pptx 要放哪裡?——不用搬

**放桌面就好,不用搬進專案資料夾。** 中文檔名可以、放在下載資料夾也可以。
工具會自己複製一份進模板包,**你桌面上的原檔完全不會被動到**。

那指令裡那串「路徑」怎麼來?也是用拖的,而且有一條鐵律:

> **先打一個雙引號 `"`,再把 .pptx 從 Finder 拖進來,再補一個雙引號 `"`。**

為什麼?因為檔名裡的空格會被電腦當成「兩個東西」。真實案例:檔名叫
`企業深色風 v2.pptx`,忘了加引號的結果是——

```
template_admin.py: error: unrecognized arguments: v2.pptx
```

訊息完全沒提到「空格」,所以你不會知道錯在哪。**加引號就沒事了。**

## A3. 每次開工第一步(順便問電腦「我該用哪個開頭」)

每次打開終端機做事,**第一行永遠是這個**:

```
python3 .codex/skills/outline-to-ppt/prepare_env.py
```

> Windows 說找不到 `python3`,就把它改成 `python`。這份文件其他指令同理:
> **Mac 用 `python3`、Windows 用 `python`**。

它會刷一串 `OK …`,最後兩行才是重點:

```
渲染指令前綴:uv run --with python-pptx python(本直譯器缺 python-pptx,改用 uv)
沙箱就緒:ppt_out/
```

**第一行就是在告訴你:碰 PowerPoint 檔的指令,開頭要加什麼。** 每台電腦答案
可能不同——如果它印的是「本直譯器已有 python-pptx」,那你就不用加前綴,
下面所有 `uv run --with python-pptx python` 都換成 `python3` 即可。

如果它印 `[E] … 不是 ppppai repo(找不到 engine/)`,代表 A1 沒站對,回去重做。

## A4. 五個步驟,照順序抄

下表的 `corp_dark`(英文代號)和 `企業深色風`(中文名)**是範例,要換成你自己的**。
英文代號**只能用小寫英文、數字、底線**(例:`corp_dark`、`retail_2026`),
中文和大寫會被擋;而且它會變成資料夾名,**取好就別再改**。

| # | 做什麼 | 指令 | 看到這行才算過 |
| --- | --- | --- | --- |
| 1 | 建立模板包 | `uv run --with python-pptx python engine/release/template_admin.py new --pptx "把檔案拖進來" --id corp_dark --name 企業深色風` | `已建包骨架:…(N 頁,status=draft)` |
| 2 | 盤點模板每頁有哪些框 | `uv run --with python-pptx python engine/release/template_admin.py freeze --id corp_dark` | `freeze 完成:N 頁快照,sha=…` |
| 3 | **請 AI 精靈接手**(見下方說明) | — | 精靈說「綁定寫好了」 |
| 4 | 產驗收檔(約 20 秒) | `uv run --with python-pptx python engine/release/template_admin.py golden --id corp_dark` | `golden PASS:N 頁 … → 目檢檔 …/ppt_out/golden_corp_dark.pptx` |
| 5 | 正式註冊(約 40 秒) | `uv run --with python-pptx python engine/release/template_admin.py register --id corp_dark` | `★ registered:corp_dark@… 全自動 N / 半自動 N / 不支援 N` |

(表中的頁數 `N` 會依你的模板而不同;`59 頁` 是內建 light 模板的數字。)

**第 3 步是關鍵,也是你唯一需要「用嘴」的地方**:在專案資料夾裡開 AI CLI
(Codex CLI 或 Claude Code),跟它說:

> 照 `.codex/skills/register-template/SKILL.md`,幫我把 `corp_dark` 這個模板包
> 的頁型映射與綁定寫好。

它會逐頁問你「第 18 頁看起來像『願景目標』還是『核心與支援』?」——
**你用嘴回答就好**,`shape id`、JSON、`bindings.json` 這些它會自己寫。
回答完它會請你跑第 4 步。

第 4 步做完,**打開驗收檔看一眼**:

```
open ppt_out/golden_corp_dark.pptx
```

Windows:到 `ppt_out` 資料夾雙擊。裡面每種頁型兩頁——**單數頁塞最少字**
(看有沒有殘留空框、斷頭的分隔線),**雙數頁塞最滿字**(看有沒有爆框)。
頁面上的「測測測測」是刻意的假字,不是 bug。

不對的地方**把頁碼告訴精靈**,它改綁定、你重跑第 4 步,直到你點頭為止。
**機器全綠也不代表視覺沒問題——所以一定要你看過。**

### 選配:不開 PowerPoint 也想快速掃一眼

```
uv run --with python-pptx --with pillow python engine/release/wireframe_preview.py --pptx ppt_out/golden_corp_dark.pptx --out ppt_out/wf
```

**注意這條開頭多了 `--with pillow`**,照抄上面那些指令的開頭會失敗。
產出是每頁一張線框 png 加一張總覽,放在 `ppt_out/wf/`。它只能看版面配置,
**字級與爆不爆框還是要以 PowerPoint 開檔為準**。

## A5. 怎麼判斷「這步過了沒」

不要用「有沒有紅字」判斷。看關鍵字:

| 你看到 | 意思 |
| --- | --- |
| `✓ corp_dark: lint OK` | 靜態檢查過了(欄位齊、頁型名合法)。**但畫面對不對還沒驗** |
| `golden PASS` | 驗收檔產好了,可以開來看 |
| `★ registered:corp_dark@…` | 註冊成功,這行後面就是你的支援矩陣 |
| `⚠ WARN` 但最後仍有 `golden PASS` | **算過**。WARN 的意思是「請你開檔看一眼」,不是不及格 |

隨時想確認狀態,這行絕對安全、想跑幾次都行:

```
python3 engine/release/template_admin.py list
```

看你的模板 status 是不是從 `draft` 變成 `registered` 了。

## A6. 我打錯會不會弄壞東西?

比你想的安全很多,而且**每條指令的影響範圍是固定的**:

| 指令 | 它會動到什麼 | 風險 |
| --- | --- | --- |
| `prepare_env` / `list` / `lint` | 只是讀跟印字(prepare_env 會刷新 `ppt_out/` 暫存區) | **零**,想跑幾次都行 |
| `new` / `freeze` / `golden` | 只寫進**你自己那個模板的資料夾** + `ppt_out/` 驗收檔 | 低,重跑會覆蓋 |
| `register` | 會把你的模板標記成「正式可用」 | 中,但它會先自己驗一輪,不過關就不會標記 |

**想更保險**:第一次練習時在指令最後加 `--packs-root ppt_out/練習包`,
整包做完丟掉也不影響正式模板區。

**這幾件事請絕對不要自己做**:手改 `engine/templates/light/` 底下任何東西、
用 Finder / 檔案總管去壓縮或解壓 zip、手改驗收 pptx 再交出去、手改
`bindings.json`。這些都有專門的指令或精靈負責。

## A7. 這些紅字是「正常的」,不是壞掉

流程中間有兩個時間點**一定會紅**,它們是中繼狀態:

| 什麼時候 | 你會看到 | 真正的意思 |
| --- | --- | --- |
| 第 2 步做完、第 3 步還沒做時跑 lint | `✗ corp_dark: 1 項  manifest 缺欄位 'page_types'` | 「你還沒告訴我每頁是什麼頁型」——正常,去做第 3 步 |
| 同上時跑 golden | `✗ corp_dark: 無 fill 頁型可驗(--page-types 過濾後為空?)` | 同上。**括號那句會讓人以為參數打錯,其實不是** |

## A8. 看到紅字,先做這三件事

1. **不要立刻再打一次同樣的指令。** 電腦不會第二次心情比較好,而且你會把
   剛剛那段錯誤訊息捲掉。
2. **看最後一行,不是第一行。** 一大段英文裡,有用的通常是最後那行。
3. **對三個最常見的原因:**

| 最後一行長這樣 | 原因 | 怎麼修 |
| --- | --- | --- |
| `unrecognized arguments: xxx.pptx` | 路徑沒用雙引號包(檔名有空格) | 重打,先打 `"` 再拖檔案再補 `"` |
| `ModuleNotFoundError: No module named 'pptx'` | 忘了加 `uv run --with python-pptx python` 開頭 | 整條重打,前綴加在**最前面** |
| `can't open file '/Users/你/Desktop/engine/…'` | 站錯資料夾(路徑中間夾著 Desktop) | 回 A1 重新 `cd` |
| `✗ 找不到模板檔:<一串路徑>` | 路徑打錯 | 拿它印的那串路徑跟桌面上的檔名逐字對 |
| `✗ id 不合法(^[a-z]…)` | 英文代號用了中文或大寫 | 改成小寫英文+底線,中文名放 `--name` |

三個都不是的話:**把整段訊息連同你打的指令一起複製**給精靈或管理者
(不要只截半張圖,最後一行往往才是關鍵)。

## A9. 什麼時候該停手、找管理者

自己來很好,但下面幾種情況**請直接停,不要硬修**:

- **同一種頁型改了三輪還是紅**:通常代表這個模板的那一頁裝不下那種頁型的
  內容量——正解是把它降級成半自動,不是繼續調。
- **`register` 出現「light 回歸紅」或「isolation 越界」**:代表有共用的東西被
  動到了,已超出單一模板的範圍。
- **驗收檔裡圖片破圖**:那是工具本身的問題,不是你的設定。
- **`register` 之後的上傳步驟**(打包 zip、傳進 GPT Builder、更新版本字串):
  這幾步本來就是管理者的工作,你不用做。
