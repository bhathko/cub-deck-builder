# 04 — 怎麼寫大綱:讓系統把你的文字變成簡報

> 這份文件回答一件事:**我手上有內容,大綱要怎麼寫,產出來的簡報才會又對又好看?**
> 你不用懂任何技術,寫完把大綱貼給簡報產生器就行。

## 分工:你顧內容,系統顧版面

| 你要做的 | 系統會做的 |
| --- | --- |
| 把要講的事寫成一份文字大綱 | 切頁、挑版面、排版、寫進模板 |
| 提供真實的數字與事實 | 逐字檢查產出沒有偏離你寫的內容 |
| 打開產出的檔案目檢 | 產完自我檢查(字數、頁碼、素材) |

## 三條鐵律

### 1. 不用切頁,不用挑版面

寫成自然的段落與條列就好,**不要**標「第幾頁」「這頁用什麼版型」。
系統會照你內容的結構自己選版面——選得不好,你目檢時指著那頁退回就行,
不需要你事先規劃版面。

### 2. 數字與事實只能由你提供

系統被設計成**絕對不會自己編數字**。你沒寫的數據,它不會「幫你補一個」,
只會放上「待補充」。所以:

- 有數據就寫進大綱(「改善後 3 天」比「變快了」能解鎖更好的版面);
- 數字**帶著單位一起寫**(「90天」「2倍」「8隊」):孤零零一個「2」太短,
  系統的逐字追溯反而對不起來,大數字版面也更好看;
- 還沒拿到的資料,自己寫「待補充」佔位,之後補了資料再重產一次;
- 「待補充」「待確認」「待定」「TBD」都是合法佔位符,但要整格單獨使用,
  不要跟自己猜的數字混在一起寫。

### 3. 短句比長句好用

每個版位能放幾個字是**拿真的模板量出來的硬上限**(卡片小標可能只有 4–6 字,
列點大多在 15 字上下)。寫大綱時往「短句、可以直接上簡報的措辭」靠,
系統就能整句照抄;寫成長文,它只能請你改短,來回就多了。

一個好用的習慣:**條列時一行講一件事,一行不超過 15 個字。**

## 內容寫出「結構」,版面就會跟著來

系統只認你文字裡**明說**的結構——它不會把並列硬掰成流程,也不會把清單
硬掰成循環。所以想要好看的版面,就把結構寫清楚:

| 你的內容寫出… | 大概會解鎖的版面 |
| --- | --- |
| 改善前 vs 改善後、方案 A vs 方案 B | 左右對照、雙方案比較 |
| 三個面向 / 三個模組 / 三個階段 | 三欄式版面 |
| 2–3 個關鍵數字(件數、百分比、時數) | 大數字 KPI 版面 |
| 日期、里程碑、時間先後 | 時間軸、階段泳道 |
| 短期 / 中期 / 長期 | 時程矩陣 |
| 由淺入深的遞進步驟 | 階梯卡 |
| 層級關係(基礎 → 進階 → 核心) | 金字塔、同心圓 |
| 固定循環(規劃 → 執行 → 檢核 → 改善) | 循環圖 |
| 6–8 個並列的小項目 | 卡片網格 |

> 版面全集會隨模板更新而增加,以「小菜單」`engine/rules/page_types_registry.md`
> 為準——那是活清單,這裡刻意不寫死有幾種。

## 不確定怎麼補結構?讓系統訪談你

大綱寫完覺得平平的,先在產生器輸入 **`/enrich-outline`**(或直接說
「幫我豐富大綱」)。它會:

1. 對照版面庫盤點你的原文,列出「補一個什麼,就能多用一種版面」的提案;
2. 缺數據的地方**用問題問你**(「有改善前後的數據嗎?」),絕不自己編;
3. 你逐項採納或拒絕;採納的增補會標上 `[補]` 記號,佔位的放「待補充」;
4. **你核准後的大綱**才會拿去產檔——你始終是內容的作者。

全部拒絕也沒關係,原稿照樣能產,只是版面會樸素一些。

## 一分鐘範例

**平鋪的寫法**(能產,但版面單調):

> 專案這半年有明顯進展,流程也比以前順了,大家配合得不錯。

**有結構的寫法**(同樣的事實,版面就有得挑):

> 上半年三個數字:上線模組 12 個、平均交付 5 天、客訴 0 件。
> 流程改善前:人工核對、來回三次。改善後:系統自動比對、一次過。
> 下半年分三階段:七月試行、八月全面導入、九月檢討優化。

## 產出之後

打開檔案逐頁目檢——**機器全綠不代表版面好看,你的眼睛是最後一關**。
有問題就指著頁碼講(「第 5 頁中間多一個圈」就是有效回饋),
回報話術參考 [01-這套工具在做什麼.md](01-這套工具在做什麼.md) 的「回饋怎麼給才有效」。
補了新資料、改了大綱,整份重產一次就好,系統每次都是重新產,不會愈改愈亂。
